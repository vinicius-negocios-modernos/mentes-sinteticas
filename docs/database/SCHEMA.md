# Database Schema — Mentes Sintéticas

> **AS-IS documentation** of the production database layer. Generated by @data-engineer (Dara) as FASE 2 of the brownfield-discovery workflow.
> **Date:** 2026-05-30
> **Source of truth:** Drizzle ORM schema (`src/db/schema/`) + applied migrations (`drizzle/*.sql`).

## Stack

| Aspect | Detail |
|--------|--------|
| Engine | PostgreSQL 16 (Docker Swarm on VPS Hostinger `76.13.82.80`, service `postgres_postgres`) |
| ORM | Drizzle ORM (`drizzle-orm/postgres-js`), driver `postgres` |
| Schema definition | TypeScript, `src/db/schema/*.ts` (one file per table) |
| Migrations | `drizzle/0000_slim_winter_soldier.sql`, `0001_cold_crystal.sql`, `0002_brown_thena.sql` (journal: `drizzle/meta/_journal.json`) |
| Migration config | `drizzle.config.ts` → `out: ./drizzle`, `dialect: postgresql`, `url: DATABASE_URL` |
| Connection | Lazy singleton (`src/db/index.ts`), pool `max: 10`, `idle_timeout: 20s`, `connect_timeout: 10s` |
| Auth model | NextAuth v5, **Credentials provider + JWT strategy** — sessions are NOT persisted to DB, so there are **no `accounts` / `sessions` / `verification_token` tables**. A custom `users` table holds bcrypt `password_hash`. |
| Schema | `public` |
| UUIDs | All PKs are `uuid DEFAULT gen_random_uuid()` |
| Timestamps | All `timestamp with time zone` (timestamptz), `DEFAULT now()` |

> **NOTE — Supabase removed.** This project no longer uses Supabase (removed in commit `aa0dade`). There are **no RLS policies**. Authorization is enforced 100% in the application/service layer (every query filters by `userId`). This is a material security/data-integrity characteristic — see DB-AUDIT.md DB-1.

## Table Inventory (11 application tables)

> Project memory references "17 tables"; that count includes Drizzle's internal `__drizzle_migrations` table and likely a historical count. The current Drizzle schema defines **11 application tables** (all listed below). No NextAuth session tables exist (JWT strategy).

| # | Table | Purpose |
|---|-------|---------|
| 1 | `users` | Authentication identities (NextAuth Credentials). Email + bcrypt `password_hash`. |
| 2 | `minds` | The synthetic minds (personas). Slug, name, era, system prompt, personality traits, greeting, avatar. |
| 3 | `knowledge_documents` | RAG source documents per mind (the corpus uploaded to Gemini). Holds `local_path` / `storage_path` / `display_name`. |
| 4 | `file_uri_cache` | Cache of Gemini File API URIs per knowledge document, with expiry (URIs live ~48h). |
| 5 | `conversations` | Chat sessions between a user and a mind. Supports public sharing via `share_token`. |
| 6 | `messages` | Individual chat turns within a conversation. `mind_slug` used for debate authorship. |
| 7 | `token_usage` | Per-message Gemini token accounting + computed cost in USD. |
| 8 | `rate_limits` | Sliding-window rate limiting per user/action. |
| 9 | `mind_memories` | Long-term per-(user, mind) memory extracted from conversations. |
| 10 | `debates` | Multi-mind debate sessions (topic, rounds, turn state, status). |
| 11 | `debate_participants` | Join table: which minds participate in a debate and their turn order. |

## Relationships (FK graph)

```
minds ──< knowledge_documents ──< file_uri_cache
minds ──< conversations ──< messages
minds ──< mind_memories
minds ──< debate_participants
conversations ──< token_usage >── messages
conversations ──< (mind_memories.source_conversation_id, SET NULL)
conversations ──< (debates.conversation_id, SET NULL)
debates ──< debate_participants
users  ──  (NO FK from anywhere — user_id is a free-floating uuid in 5 tables)
```
